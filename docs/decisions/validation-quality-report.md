# Implementation Plan: FK Validation + Statistical Quality Matrix

## Date
2026-06-27

## Status
In Progress

## Context

The calibration pipeline currently lacks two key capabilities:

1. **No ground-truth FK validation.** The existing `export_with_verification()` calls
   `trajectory_errors()`, which compares nominal FK vs calibrated FK at random
   configurations. This only answers "did the URDF change?", not "did it get better?"
   Proper validation requires comparing FK predictions (nominal and calibrated) against
   held-out ground-truth measurements.

2. **No comprehensive quality diagnostics.** The solver produces an `OptimizeResult` from
   scipy, but there is no structured output of statistical criteria (per-DOF residuals,
   condition number, parameter correlation, R², etc.) to assess calibration quality.

The calibration data is generated by `optimal_config` (information-rich, designed to
excite specific parameters). Automatic hold-out splitting risks losing these
information-rich data points. Therefore, validation data must be collected separately.

## Decisions

### D1: Separate validation data, no auto-split

| Data | Source | Configurations | Purpose |
|------|--------|---------------|---------|
| Calibration | `optimal_config` output | Designed to excite parameters | Optimize parameters |
| Validation | Separately collected | Random / workspace-covering | Test FK improvement |

Rationale: `optimal_config` generates configurations that maximize parameter
observability. Splitting this dataset risks removing information-rich points from
training. Separate validation with different configurations tests generalization.

### D2: Validation metrics computed in the calibrator, not in export_validation

Rationale: `calc_updated_fkm()` uses the nominal pinocchio model plus parameter
corrections — both nominal and calibrated FK can be computed directly without needing the
exported URDF file. This keeps validation independent of the URDF export step and
provides feedback immediately after optimization.

### D3: Quality report printed after every `solve()` call

No flag needed. The report is the calibration's primary output and should always be shown.

### D4: Correlation matrix always computed, only high pairs (|ρ| > 0.8) printed

Full correlation matrix is saved in `.npz` for post-hoc analysis. The terminal report
only lists strongly correlated pairs to stay compact.

### D5: Current FK comparison renamed, not removed

`trajectory_errors` → `fk_consistency_check`. It verifies the exported URDF file
reproduces the calibrated FK numerically — a file-integrity check, not a validation.

## Implementation Phases

### Phase 1: Validation data support

**Files:** `figaroh/src/figaroh/calibration/base_calibration.py`

| # | Task | Details |
|---|------|---------|
| P1.1 | `_load_validation_data(path)` | Loads separate CSV via existing `load_data()`; stores `self._q_val`, `self._PEE_val`; sets `self._val_available = True` |
| P1.2 | `_compute_validation_metrics()` | For each validation sample: compute nominal FK (`calc_updated_fkm` with zeros) and calibrated FK (`calc_updated_fkm` with calibrated params); compare both against measured poses via `_compute_logmap_residuals()`; aggregate position/orientation RMSE, max, and improvement % |
| P1.3 | Integration in `solve()` | After `_store_optimization_results()`, call `_compute_validation_metrics()` if `self._val_available` |

### Phase 2: Statistical quality matrix

**Files:** `figaroh/src/figaroh/calibration/base_calibration.py`

| # | Task | Details |
|---|------|---------|
| P2.1 | Per-DOF residual breakdown | Enhance `_evaluate_solution()` to decompose residuals into (x, y, z, rx, ry, rz) components. Compute mean, std, RMSE, max, R² per DOF |
| P2.2 | Condition number | `np.linalg.cond(result.jac)` — include interpretation label |
| P2.3 | Correlation matrix | From existing `C_param`, compute correlation = `C_param / outer(D, D)`. Flag pairs > 0.8 |
| P2.4 | `print_quality_report()` | Format and print the full quality table to terminal. Sections: convergence, per-DOF residuals, overall, validation (if available), parameter uncertainty top-5, correlated pairs |
| P2.5 | Call `print_quality_report()` in `solve()` | After all computation is done, print the report |
| P2.6 | Enhanced `.npz` saving | Extend `_store_optimization_results()` to include per-DOF stats, condition number, covariance, correlation, validation metrics in `results_data` |

### Phase 3: Rename FK comparison

**Files:** `figaroh/src/figaroh/tools/export_validation.py`

| # | Task | Details |
|---|------|---------|
| P3.1 | Rename method | `trajectory_errors()` → `fk_consistency_check()` |
| P3.2 | Rename class | `TrajectoryErrors` → `FkConsistencyResult` |
| P3.3 | Update docstring + printed label | Make clear this is a file-integrity check, not validation |

### Phase 4: Script updates

**Files:** `figaroh-examples/examples/{tiago,ur10,talos}/calibration.py`

| # | Task | Details |
|---|------|---------|
| P4.1 | Update `export_with_verification()` | Use renamed `fk_consistency_check()`; update printed labels |
| P4.2 | Add `--validation-data` CLI flag | Pass through to calibrator |
| P4.3 | Config template | Add optional `validation.data_file` field to unified config |
